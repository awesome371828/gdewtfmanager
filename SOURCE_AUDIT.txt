АУДИТ СТРУКТУРЫ РЕПОЗИТОРИЯ GDE.WTF MANAGER
Дата обновления: 2026-10-26

Основная точка запуска: iris.py
Runtime: Python 3.11, aiogram 3, aiohttp, PostgreSQL через postgres_adapter.py.
База данных: schema.sql.
Общие функции и устойчивое хранение очереди активности: pear_core.py.
Запуск контейнера: Dockerfile + entrypoint.sh.

Архитектурные уточнения:
- iris.py — основной исполняемый бот. Он содержит встроенную интеграцию команд GDE.WTF с префиксом !.
- postgres_adapter.py выполняет SQL-запросы через psycopg; DATABASE_URL обязателен для основного бота.
- moderation_full.py — отдельный legacy-модуль. Его компиляция проверяется при сборке образа, но он не импортируется основной точкой запуска iris.py.
- Прежний дублирующий модуль интеграции удалён: он не входил в runtime-образ и расходился с действующим обработчиком. Единственная рабочая реализация команд `!` находится в iris.py.
- tests/ содержит регрессионные проверки. Dockerfile запускает py_compile и unittest discovery при сборке; .dockerignore не исключает каталог tests.
- Telegram polling conflict (409) должен завершать процесс с кодом 23 вместо бесконечных повторных попыток в том же контейнере. Для работы требуется ровно один активный экземпляр с данным токеном.

Ограничения проверки:
- Сборка контейнера и unit-тесты должны считаться пройденными только после фактического выполнения Docker build.
- Наличие кода и статических проверок само по себе не доказывает, что внешний GDE.WTF API отвечает вовремя, Telegram принимает команды или конфигурация хоста корректна.
- Живые проверки требуют рабочего TELEGRAM_BOT_TOKEN, DATABASE_URL, GDEWTF_API_KEY и единственного активного экземпляра бота. Секреты нельзя записывать в репозиторий.
